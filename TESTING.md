# Проверка лабораторной перед сдачей

## 1. Две обязательные команды

В терминале PyCharm, в папке с `main.py`:

```text
python -m unittest discover -s tests -v
python main.py --demo
```

Ожидается: `Ran 69 tests ... OK`; затем 7 принятых шагов,
`ЦЕЛЬ ДОСТИГНУТА`, `Ошибок или отклонённых строк: 0`.

Автоматические проверки охватывают парсер, структуру формул, β, MP,
историю, цель, сброс, консоль, файлы, кодировки и коды завершения.
Внутри отдельных тестов перебираются подслучаи, включая 1000 воспроизводимых
случайных строк и сгенерированные допустимые подстановки.
Это проверка перечисленных классов случаев, а не обещание отсутствия
любых возможных ошибок на всех входах и во всех окружениях.

## 2. Как выполнять ручные сценарии

```text
python main.py
```

После запуска перед каждым независимым сценарием вводите `/reset`.
Строки из блоков ниже вводятся последовательно, по Enter после каждой.
Сценарии с MP требуют предварительно выполнить указанные шаги.

## 3. Правильно построенные формулы

```text
/parse p
/parse !p
/parse !!p
/parse p -> q
/parse !(p -> q)
/parse (((a) -> b)) -> (f -> ((p -> (q))))
/parse ¬p ⊃ (q → p)
/list
```

Ожидается: каждый `/parse` сообщает `ЗАПИСЬ КОРРЕКТНА`.
`/list` показывает аксиомы и отсутствие принятых шагов.
Проверка синтаксиса ничего не доказывает.

## 4. Приоритет и скобки

| Ввод | Нормализованная формула |
|---|---|
| `/parse !p -> q` | `(!p -> q)` |
| `/parse !(p -> q)` | `!(p -> q)` |
| `/parse p -> q -> r` | `(p -> (q -> r))` |
| `/parse (p -> q) -> r` | `((p -> q) -> r)` |
| `/parse ((p))` | `p` |

Разные смысловые скобки дают разные деревья. Избыточные парные скобки
не влияют на результат разбора.

## 5. Неправильно построенные формулы

Каждую строку вводите отдельно:

```text
p -> (p -> p))
mn -> (p -> p)
q -> (p p)
-> a -> b -> c
a -> b -> c ->
()
!
p -> !
(p -> q
p q
p(q)
p !q
p -> -> q
p & q
p | q
p1
P
```

Ожидается: `ОШИБКА ЗАПИСИ` с причиной и позицией.
Кириллическая `р`, визуально похожая на латинскую `p`, тоже отклоняется.
После любого числа ошибок программа продолжает принимать команды и формулы.

Пустой Enter просто показывает новое приглашение. Пустая строка в самой
функции `parse_formula` является ошибкой — это проверено автоматическим тестом.

## 6. Запись верная, но доказательства пока нет

```text
/reset
p
p -> p
/list
```

Ожидается: оба шага не приняты; список шагов пустой.
`p -> p` — теорема, однако промежуточное доказательство ещё не предъявлено.
`p` не становится известной только потому, что встречается внутри аксиом.

## 7. Аксиомы и дубликаты

```text
/reset
p -> (q -> p)
(s -> (p -> q)) -> ((s -> p) -> (s -> q))
(!p -> !q) -> (q -> p)
p -> (r -> p)
((p) ⊃ ((r) → (p)))
/list
```

Первые три строки — уже известные аксиомы A1–A3.
Четвёртая формула — шаг 1, β из A1, `q := r`.
Последняя формула совпадает с шагом 1, несмотря на скобки и обозначения.
В списке остаётся ровно один пользовательский шаг.

## 8. Только одна переменная за шаг

```text
/reset
a -> (b -> a)
a -> (q -> a)
a -> (b -> a)
```

Ожидается:

1. Отказ: для прямого получения из A1 требуются две замены.
2. Шаг 1: `p := a` в A1.
3. Шаг 2: `q := b` в шаге 1.

Именно это отличает требуемое задание от автоматического распознавания
любых экземпляров схем аксиом.

## 9. Все вхождения должны заменяться одинаково

```text
/reset
r -> (q -> p)
r -> (q -> s)
r -> (q -> r)
```

Первые две формулы отклоняются. Последняя принимается: все исходные `p`
в A1 заменены одной и той же формулой `r`.

## 10. Сложная замена, содержащая собственную переменную

```text
/reset
(p -> r) -> (q -> (p -> r))
```

Ожидается: β из A1, `p := (p -> r)`.
Внутри вставленной формулы повторная замена не выполняется.
Исходная A1 остаётся неизменной.

## 11. Третья аксиома и отрицание

```text
/reset
(!!r -> !q) -> (q -> !r)
(!!r -> !(a -> b)) -> ((a -> b) -> !r)
```

Ожидается:

1. β из A3: `p := !r`.
2. β из шага 1: `q := (a -> b)`.

Или выполните готовый файл:

```text
python main.py --file examples/negation.txt
```

## 12. Полное доказательство с MP

```text
/reset
/goal p -> p
(s -> (r -> q)) -> ((s -> r) -> (s -> q))
(p -> (r -> q)) -> ((p -> r) -> (p -> q))
(p -> (r -> p)) -> ((p -> r) -> (p -> p))
p -> (r -> p)
(p -> r) -> (p -> p)
(p -> (q -> p)) -> (p -> p)
p -> p
/list
```

| Шаг | Правило | Источник / замена |
|---|---|---|
| 1 | β | A2, `p := r` |
| 2 | β | Шаг 1, `s := p` |
| 3 | β | Шаг 2, `q := p` |
| 4 | β | A1, `q := r` |
| 5 | MP | Шаги 3 и 4 |
| 6 | β | Шаг 5, `r := (q -> p)` |
| 7 | MP | Шаг 6 и A1 |

В конце цель достигнута. Каждое объяснение MP содержит A -> B, A и B.

## 13. Для MP нужны обе посылки

Сбросьте сеанс. Выполните только первые три формулы доказательства выше.
Попробуйте ввести:

```text
(p -> r) -> (p -> p)
```

Ожидается отказ: импликация есть, но её левая часть ещё не доказана.
Теперь введите:

```text
p -> (r -> p)
(p -> r) -> (p -> p)
```

Обе строки принимаются: после появления недостающей посылки MP разрешён.

## 14. Запрет объединять подстановку и MP

В новом сеансе выполните первые пять формул полного доказательства.
Сразу введите `p -> p`: ожидается отказ. Затем введите шаг 6 и повторите
`p -> p`: обе строки принимаются. Программа не придумывает скрытый шаг 6.

## 15. Опечатка со скобками из методички

В новом сеансе выполните первые четыре формулы полного доказательства.
Введите:

```text
p -> r -> (p -> p)
```

Ожидается отказ: по принятому соглашению это `p -> (r -> (p -> p))`.
Правильный результат MP:

```text
(p -> r) -> (p -> p)
```

## 16. MP нельзя применять в обратную сторону

```text
/reset
(p -> (q -> p)) -> (q -> (p -> (q -> p)))
q -> (p -> (q -> p))
q
```

Первый шаг: подстановка `p := (p -> (q -> p))` в A1.
Второй: MP из шага 1 и A1. Получена формула `q -> A1`.
Последний ввод `q` отклоняется: из `q -> A1` и `A1` нельзя заключить `q`.

## 17. Цель и просмотр синтаксиса не создают посылки

```text
/reset
/goal p
/parse p
p
q -> p
/list
```

Оба пользовательских шага отклонены; список шагов пустой; цель не достигнута.

## 18. Состояние после ошибок и сброс

```text
/reset
p ->
p
p -> (r -> p)
/goal p -> p
/goal p ->
/list
/reset
/list
```

После первых двух ошибок следующая допустимая формула становится именно
шагом 1. Неправильно записанная новая цель не удаляет цель `p -> p`.
После `/reset` остаются только три аксиомы, без шагов и цели.

## 19. Ошибки команд, файлов и завершение

```text
/unknown
/goal
/parse
/exit extra
/help
```

Первые четыре команды сообщают об ошибке; последняя показывает справку.
Корректный `/exit` завершает работу. Ctrl+C обрабатывается без traceback.
Конец ввода также завершает программу: на Windows обычно Ctrl+Z и Enter,
на Linux/macOS — Ctrl+D.

Для проверки отсутствующего файла:

```text
python main.py --file missing.txt
```

Ожидается сообщение об ошибке файла, код 2, без traceback.

Для набора намеренных ошибок:

```text
python main.py --file examples/errors.txt
```

Ожидается код 1; последняя допустимая формула всё равно принимается как шаг 1.

## 20. Что объяснить преподавателю

- **Зачем дерево:** отличать структуру от внешнего вида строки, сохранять
  группировку и выполнять структурное сравнение.
- **Зачем неизменяемость:** подстановка не должна переписывать старый шаг.
- **Что делает MP:** ищет конкретные известные A -> B и A для введённой B.
- **Что делает β:** распознаёт одну переменную и единую формулу замены
  для всех её вхождений.
- **Почему нет таблиц истинности в рабочем алгоритме:** требуется проверить
  предъявленный шаг доказательства. Истинность формулы не заменяет обоснование.
- **Почему p -> p иногда отклоняется:** теорема ещё не получена разрешённым
  шагом из текущих известных формул.
- **Почему a -> (b -> a) сначала отклоняется:** по условию нельзя скрыть
  две подстановки в одном шаге.
- **Что происходит с ошибками:** состояние сеанса не меняется; ввод продолжается.
- **Какие ограничения выбраны:** переменные a-z, правоассоциативная импликация,
  ограничения размера и глубины; всё явно описано в README.
