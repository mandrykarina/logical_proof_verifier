# Лабораторная работа № 1. Вариант 2

Дискретная математика: неклассические логические вычисления.

Консольный верификатор доказательств в исчислении высказываний.
Пользователь вводит формулы по одной. Программа проверяет синтаксис,
затем обоснование одного шага и сохраняет только принятые формулы.
Она проверяет предъявленное доказательство, а не ищет его автоматически.

## Соглашения о записи

- Переменная — одна маленькая латинская буква `a`–`z`.
- `->`, `→`, `⊃` обозначают одну операцию импликации.
- `!`, `¬` обозначают отрицание.
- Пробельные символы пропускаются. `pq` и `p q` всё равно являются ошибкой:
  между переменными нет операции.
- Отрицание имеет более высокий приоритет: `!p -> q` = `(!p) -> q`.
- Импликация правоассоциативна: `p -> q -> r` = `p -> (q -> r)`.
- Скобки меняют группировку: `(p -> q) -> r` — другая формула.
- Дополнительные парные скобки разрешены: `(((p)))` = `p`.
- Константы истинности, многобуквенные имена, большие буквы, кириллица,
  конъюнкция, дизъюнкция и другие операции в данном варианте не поддерживаются.
- Для наглядности вывод содержит скобки вокруг каждой импликации.

Это явные соглашения реализации. В методичке установлена односимвольность
переменных; алфавит `a`–`z` и правоассоциативность зафиксированы здесь, поскольку
в предоставленных PDF нет полной грамматики лекции.

## Команды

| Команда | Действие |
|---|---|
| `/help` | Справка |
| `/list` | Аксиомы и принятые шаги с обоснованиями |
| `/goal p -> p` | Задать цель доказательства |
| `/parse !(p -> q)` | Проверить только синтаксис и показать структуру через расстановку скобок |
| `/reset` | Очистить шаги и цель; аксиомы остаются |
| `/exit` | Завершить работу |

Команды чувствительны к регистру. `/goal` и `/parse` требуют аргумент-формулу.
Остальные команды аргументов не принимают. Ошибочная команда не меняет сеанс.
Ошибочно записанная новая цель не затирает предыдущую.

Цель не является посылкой: `/goal p` не даёт права использовать `p` в MP.
`/parse` тоже ничего не добавляет в доказательство.
Повторный ввод аксиомы или известной формулы сообщает её источник и не создаёт
дубликат шага. Пустая строка в интерфейсе пропускается; пустая формула при
вызове парсера считается ошибкой.

## Пример сеанса

```text
Формула > p -> (r -> p)
ПРИНЯТО — шаг 1
Формула: (p -> (r -> p))
Правило: бета (подстановка).
  Источник [A1]: (p -> (q -> p))
  Замена: q на r
  Заменены все вхождения одной переменной; остальные части сохранены.
Формула добавлена в доказательство.
```

Если введено `p ->`, программа сообщает об ошибке записи и позиции.
Если введено `p`, запись корректна, но шаг не обоснован: программа сообщает
об этом отдельно. «Шаг не принят» не означает «формула ложная» или
«формулу невозможно доказать».

## Проверка файла

```text
python main.py --file examples/proof_p_implies_p.txt
python main.py --file examples/negation.txt
python main.py --file examples/atomic_substitution.txt
python main.py --file examples/errors.txt
```

Формат: UTF-8, одна формула или команда на строку. UTF-8 BOM и окончания строк
Windows поддерживаются. Пустые строки и строки, начинающиеся после пробелов
с `#`, пропускаются. Комментарий должен занимать отдельную строку; комментарии
после формулы не поддерживаются. `/exit` явно прекращает чтение файла.

Ошибки отдельных строк не останавливают чтение, но приводят к ненулевому
итоговому коду. Отклонённые формулы не используются в последующих шагах.
Файл `errors.txt` специально содержит ошибки: для него код 1 — ожидаемый результат.

| Код завершения | Значение |
|---|---|
| 0 | Проверка файла успешна; если цель задана, она достигнута |
| 1 | Есть ошибки строк/отклонённые шаги, нет формул или не достигнута цель |
| 2 | Ошибка чтения файла, кодировки, размера или параметров запуска |
| 130 | Пользователь прервал выполнение через Ctrl+C |

В интерактивном режиме штатный `/exit` или конец ввода возвращают 0,
независимо от ошибок, которые пользователь исправлял во время работы.

Посмотреть код завершения в PowerShell:

```text
$LASTEXITCODE
```

Сохранить вывод демонстрации в текстовый файл:

```text
python main.py --demo > demo_output.txt
```

## Устройство и алгоритмы

### 1. Дерево формулы

`Var(name)` хранит переменную, `Not(operand)` — отрицание,
`Implies(left, right)` — импликацию. Объекты неизменяемы (`frozen=True`).
Сравнение полей рекурсивно сравнивает структуру. Хеширование позволяет использовать
формулу ключом словаря. Равносильные, но разные по структуре выражения,
например `p` и `!!p`, не считаются одной формулой.

### 2. Разбор текста

Лексер выделяет токены и их позиции. Парсер рекурсивным спуском реализует:

```text
implication := unary [ IMPLIES implication ]
unary       := NOT unary | atom
atom        := VARIABLE | '(' implication ')'
```

Прямоугольные скобки в этой записи грамматики означают необязательную часть,
а не допустимый символ пользовательской формулы. `eval` не используется.
После построения дерева проверяется, что разобран весь ввод.

### 3. Состояние доказательства

Словарь `формула -> Entry` содержит аксиомы и принятые шаги. `Entry` хранит
метку, дерево, правило, источники и параметры подстановки. Отдельный список
сохраняет порядок пользовательских шагов. Метод `reset` восстанавливает
исходное состояние. История наружу возвращается неизменяемым кортежем.

### 4. Modus ponens

Для введённой B перебираются известные импликации. Если правая часть
импликации совпадает с B, проверяется наличие её левой части A в словаре.
Только при наличии обеих формул A и A -> B принимается B.
Посылки могут быть сложными формулами и исходными аксиомами.

### 5. Атомарная подстановка β

Для каждой известной исходной формулы по очереди проверяется каждая
встречающаяся в ней переменная. При первом вхождении выбранной переменной
запоминается соответствующее поддерево результата. На всех остальных её
вхождениях требуется то же поддерево. Все остальные переменные и операции
обязаны совпадать. Перебора всех возможных замен нет: кандидат берётся
непосредственно из результата пользователя.

Замена одной переменной выполняется во всех её исходных вхождениях.
Вставленная формула может сама содержать заменяемую переменную: это
не приводит к повторной замене внутри вставки.

`substitute` непосредственно выполняет замену в дереве, а `infer_substitution`
распознаёт её между исходной и введённой формулами. Рабочий верификатор
использует распознавание; прямое выполнение используется в автоматических
проверках для сопоставления ожидаемых результатов.

Сначала проверяется известная формула, затем MP, затем β. При нескольких
обоснованиях выбирается первое в постоянном порядке: аксиомы A1–A3, затем
принятые шаги; переменные — по алфавиту.

Нельзя автоматически принимать произвольный экземпляр схемы аксиомы,
скрывать несколько β в одной строке или объединять β и MP в один шаг.
Например, `a -> (b -> a)` сначала отклоняется. После ввода
`a -> (q -> a)` эта же формула принимается следующей подстановкой.

### 6. Оценка трудоёмкости

Пусть N — число символов ввода, M — число известных формул, L — верхняя
оценка размера сравниваемых деревьев, V — число разных переменных
в исходной формуле (здесь не более 26).

- Лексический и синтаксический анализ: O(N), память O(N).
- Один поиск MP: O(M * L), учитывая сравнение и вычисление хеша деревьев.
- Поиск β: консервативная верхняя оценка O(M * V * L²), поскольку при
  повторных вхождениях сравниваются поддеревья замены. На небольших учебных
  формулах это не является узким местом.
- История занимает память пропорционально суммарному размеру сохранённых формул.

Операции со словарём имеют ожидаемую постоянную стоимость после вычисления
хеша; хеш неизменяемого дерева `dataclass` здесь не кешируется.

## Ограничения на ресурсы

Чтобы случайный огромный ввод не приводил к необработанному переполнению
стека, введены явные ограничения:

- 10 000 символов в одной формуле;
- 2 000 токенов;
- 100 уровней в дереве формулы;
- менее 200 вложенных синтаксических переходов при разборе (с учётом скобок);
- 1 МиБ на входной файл.

Превышение — сообщение об ограничении, а не утверждение о математической
некорректности формулы. Синтаксический предел выше глубины дерева, чтобы
выведенная с полными скобками формула предельной глубины читалась обратно.
Число шагов искусственно не ограничено; состояние хранится в памяти сеанса.
После закрытия программы оно не сохраняется автоматически.

## Исправления опечаток методички

1. В `p -> (p -> p))` лишняя закрывающая, а не открывающая скобка.
2. В третьем шаге доказательства подстановка `q := p` применяется к результату
   второго шага, а не к указанной в методичке формуле с переменной `s`.
3. Результат первого MP: `(p -> r) -> (p -> p)`. Скобки вокруг левой
   импликации обязательны. Запись `p -> r -> (p -> p)` имеет другую структуру
   при принятой правоассоциативности.
4. Исправлена повторяющаяся нумерация шага 4: в примере семь шагов.
5. Запрет начинать формулу операцией относится к бинарной импликации.
   Начальное отрицание `!p` разрешено в варианте 2.

Аксиомы варианта 2 и ограничение на одиночную подстановку сохранены.
